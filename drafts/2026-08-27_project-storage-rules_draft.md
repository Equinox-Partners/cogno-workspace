# Cogno クライアントワーク プロジェクト格納ルール設計

> 作成日: 2026-08-27 / Task #6567

## 背景と目的

Cognoでクライアントワークが増えるにつれ、異なる企業との会議から生まれたタスクが
「デフォルトプロジェクト」に溜まりつつある（現在64件）。
会議ごとにタスクを適切なプロジェクトへ自動振り分けすることで、
案件ごとの進捗追跡と見通しを改善する。

## 振り分けルール（優先順位順）

### Rule 1: 会議タイトルのキーワードマッチ（最優先）

会議タイトルに以下のキーワードが含まれる場合、対応プロジェクトへ振り分ける。

| キーワード（部分一致）               | 振り分け先                |
|----------------------------------|--------------------------|
| `EmbodyMe` / `embodyMe`          | EmbodyMe (387)           |
| `Veritas`                        | Veritas株式会社 (402)     |
| `いいんじゃ`                      | いいんじゃ (389)           |
| `cogno` / `Cogno`（定例・MTG系） | cogno環境再構築 (386)     |
| `勉強` / `学習` / `研究`          | 勉強 (403)               |

**例:**
- `Veritas MTG` → Veritas株式会社 (402)
- `EmbodyMeよもやま会` → EmbodyMe (387)
- `cogno定例MTG` → cogno環境再構築 (386)

---

### Rule 2: 参加者ドメイン・所属マッチ

会議の参加者情報から会社を特定できる場合に適用する。
（Rule 1でマッチしなかった場合にフォールバック）

| 参加者所属                     | 振り分け先                |
|------------------------------|--------------------------|
| EmbodyMe関係者               | EmbodyMe (387)           |
| Veritas関係者                | Veritas株式会社 (402)     |
| いいんじゃ関係者              | いいんじゃ (389)           |
| Equinox Partners内部メンバーのみ | → Rule 3へ              |

---

### Rule 3: 会議タイプによる内部分類

参加者が全員Equinox Partners内部の場合：

| 会議内容の判断基準                          | 振り分け先                |
|------------------------------------------|--------------------------|
| Cognoツール・自動化・ワーカー設定の話題      | cogno環境再構築 (386)     |
| よもやま会（接頭辞なし・社内雑談型）         | デフォルトプロジェクト (294)|
| Equinox Partners定例                      | デフォルトプロジェクト (294)|

---

### Rule 4: 複数クライアント混在の場合

1つの会議に複数クライアントが登場する場合（例: EmbodyMeといいんじゃが同席）：

- **会議の主催者/主テーマのクライアント**のプロジェクトへ振り分ける
- 判断できない場合はデフォルトプロジェクト (294) へ格納し、手動レビューフラグを立てる

---

### Rule 5: 新規企業（未登録クライアント）

プロジェクトが存在しない企業からのタスクが発生した場合：

1. デフォルトプロジェクト (294) に一時格納
2. Cognoのattentionまたはタスクで「新規プロジェクト作成の提案」を通知
3. 同じ会社のタスクが3件以上蓄積されたら、新規プロジェクト作成を推奨

**判断の目安:**
- 1〜2件 → デフォルトに格納しつつタグで会社名を付与
- 3件以上 → プロジェクト作成を提案

---

## 振り分けフローチャート

```
会議からタスクが生成される
        ↓
[Rule 1] タイトルにキーワードが含まれる？
    YES → 対応プロジェクトへ振り分け ✅
    NO  ↓
[Rule 2] 参加者の所属が特定できる？
    YES → 対応プロジェクトへ振り分け ✅
    NO  ↓
[Rule 3] 全員Equinox内部 + 会議タイプ判定
    Cogno系 → cogno環境再構築 ✅
    その他  → デフォルトプロジェクト ✅
        ↓
[Rule 4] 複数クライアント混在の場合
    主催者/主テーマで判定 → 対応プロジェクト ✅
    判断不可 → デフォルト + 手動レビューフラグ ⚠️
        ↓
[Rule 5] 新規企業のタスク
    3件未満 → デフォルト + 会社名タグ付与
    3件以上 → 新規プロジェクト作成を提案
```

## よもやま会の扱い（特記事項）

現在「よもやま会」という名称の会議が複数存在し、扱いが曖昧になっている：

| 会議名                  | 振り分け先             | 根拠                        |
|------------------------|----------------------|----------------------------|
| `EmbodyMeよもやま会`    | EmbodyMe (387)       | 接頭辞でクライアント特定      |
| `よもやま会`（接頭辞なし）| デフォルト (294)     | 内容が複数案件混在のため      |

→ **推奨:** よもやま会の命名規則を `[会社名]よもやま会` に統一することで自動判定精度が上がる。

## 実装上の留意点

1. **タスク生成タイミング**: 振り分けは会議終了直後のタスク生成時に実施
2. **後からの修正**: 振り分けミスは手動でプロジェクトを変更可能
3. **Cogno側の設定**: プロジェクトの「指示」欄に対象企業名・キーワードを明記することで、
   将来の自動判定精度向上に貢献する
4. **デフォルトプロジェクトの定期見直し**: 月1回、デフォルトプロジェクトのタスクを
   確認し、適切なプロジェクトへ移動するレビューを推奨
